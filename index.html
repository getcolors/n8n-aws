DEPLOYMENT · AWS · N8N ON SELF-HOSTED NEON

n8n-aws

Desired state for one self-hosted n8n server on an EC2 instance in us-east-1a: n8n behind Caddy with an external task runner, on a colocated self-hosted Neon whose layers, WAL and six-hourly backups live in S3 buckets this deployment creates and deletes.

Every bucket is an owned resource. create makes the OpenTofu state bucket, the Neon data bucket and the backup bucket, mints one bucket-scoped IAM key for each, and delete removes all of them again with their contents. Nothing is prepared by hand in the AWS console, and the storage stage refuses to adopt a bucket that already exists.

What is tracked here

colors.yml (the only editable desired state), the installed n8n Package Skill payload and lockfile, a root launcher copied from that payload, toolchain files, and documentation. Credentials live in gitignored .envrc.private; generated output in .colors/ is never committed.

Lifecycle

direnv allow               # once, after cloning
./green build              # render .colors/n8n-aws/ — contacts nothing
./green create --dry-run   # walk the workflow, no side effects
./green create             # converge (requires authorization)
./green delete             # guarded and destructive

Credentials

Three operator credentials: the AWS pair (mapped onto the ambient credential chain by .envrc), a zone-scoped Cloudflare token, and the n8n encryption key. No bucket credentials: the storage stage mints scoped keys from OpenTofu output and hands them to Ansible in memory.

The encryption key outlives the host. n8n writes it into its settings file on first boot and refuses to start if the environment later disagrees. Keep a copy somewhere that is not this machine.
